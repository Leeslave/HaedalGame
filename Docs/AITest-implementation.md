# AITest 기획 구현

작업 브랜치: feature/AITest. 비교 기준: 기획 대비 점검 보고서 44개 항목.

## 적용 기준

- 데이터: 첨부 엑셀 22종 메뉴 / 28종 재료. 별은 연구 난이도, F~A는 재료·음식 품질로 구분.
- 레벨 제한: 2026-06-10 종합표(하루 10~70명, 최대 26석).
- 기본 연구: 미니게임 성공 해금. 일수 연구는 별도 선택 가능한 규칙이며 동시에 강제하지 않는다.
- 첫 도구 선택 후 기본 메뉴 중 만들 수 있는 메뉴를 사용. Lv.2~4에 추가 도구 선택.
- 영업 종료는 당일 자유시간으로 이동. 취침 시 주급/연구/공사/상점 갱신과 함께 다음 날 체크포인트 저장.
- 실험 저장 파일 `savegame-aitest.json`을 사용. 기존 `savegame.json`은 데이터 ID 변경 때문에 자동 이관하지 않으며 덮어쓰지 않는다.
- 아트가 없는 신규 콘텐츠는 기존 게임 리소스와 텍스트 UI를 사용하는 플레이 가능한 표현으로 연결한다. 최종 아트 납품과 동일한 완료 상태로 기록하지 않는다.

## 이번 추가 수정

- 연구 실습의 동일한 타이밍 버튼 6회를 각 단계별 조작으로 교체했다. 실습을 닫으면 예약은 유지하며 다시 시작할 수 있다.
- 점수에 NaN·무한대·범위 밖 값이 들어오면 해금을 거절한다. 성공은 4~5점이며 이미 완료한 연구는 다시 보상하지 않는다.
- 기존 MinigameManager도 컨트롤러 누락 시 자동 성공하지 않고, 시작 전 연결 검사를 거친 뒤 재료를 원자적으로 소비한다. 새 관리 창의 공통 실습과는 별도 경로이다.
- 테이블 이동 시 색상을 보존하고 배치 취소 시 오버레이를 정리한다.
- 자동 메뉴 편성에서 당일 사용했던 메뉴를 불필요하게 제외하던 조건을 제거했다. 일일 종류 제한은 공용 검증을 따른다.
- 타이틀 환경 설정 및 저장된 전체 화면 설정 복원을 연결했다.

## 검증 결과와 한계

- `compile_check.py`: 설치된 Roslyn과 Unity 프로젝트 참조를 사용한 Assembly-CSharp / Assembly-CSharp-Editor 정적 컴파일 통과.
- `validate_aitest_assets.py`: 원본 엑셀과 22종 메뉴·28종 재료·양념 6종의 이름, 수량, 가격, 조리 유형·시간 대조 통과. 신규 리소스 GUID·메타와 도구 용량 검증 통과.
- `git diff --check`: 공백 오류 없음. Git의 LF → CRLF 경고만 존재한다.
- EditMode 테스트 소스: 저장 실패 시 원자성, 재료 등급·중복 요구량, 메뉴 변경, 연구 취소 환불·해금 점수·중복 완료 방지, 타이밍 경계값 등을 추가했다. 테스트 소스 정적 컴파일은 통과했지만 테스트 실행은 하지 못했다.
- Unity 6000.3.8f1 배치 실행은 유효한 Editor 라이선스가 없어 종료했다. `Temp/aitest-compile.log`에 관련 로그가 있다. 따라서 Unity 임포트, EditMode/PlayMode 테스트, 실제 클릭 동작과 빌드 성공은 아직 확인하지 못했다.

## Unity에서 이어서 검증할 순서

1. StartScene_TEST에서 새 게임, 첫 도구 선택, 메뉴 등록, 첫 영업과 정산, 당일 자유시간, 취침과 이어하기.
2. 연구 설계도 구매와 재료 예약, 실습 실패·닫기·재도전·성공, 취소 환불. 성공 기준은 6단계 평균 4/5점.
3. 레벨 상승과 도구 강화, 복합 조리, 재료 품절, 직원 체력·깨우기·주급 부족과 해고.
4. 테이블 회전·이동·색상·취소·되돌리기 후 취침 저장과 재실행. 실제 손님의 경로와 좌석 방향 확인.
5. 탐험 요청과 챕터 진행, 배 부품·출항·후일담, 창 모드와 전체 화면에서 UI 확인.

## 데이터 재생성과 실험값

`import_planning_data.py <원본.xlsx>`는 RecipeDatabaseSO를 다시 생성한다. 현재 아이콘 참조는 비어 있으므로 수동 아이콘 연결 후에는 재생성에 주의한다.
`prepare_aitest_assets.py`는 신규 메타와 엘프·강화 리소스를 준비한다. 도구 리소스를 재작성하므로 밸런스를 수동 수정한 뒤에는 변경 내용을 먼저 비교한다.
가격·도구 상위 강화·탐험 보상 등의 원문에서 확정하지 못한 값은 플레이 연결을 위한 실험값이다. 모든 기획 항목이 최종 구현 완료된 상태로 보지 않는다.
