# HaedalGame

Unity 기반 2D 식당 경영 시뮬레이션 팀 프로젝트입니다.
손님 입장부터 좌석 배정, 주문, 서빙, 퇴장까지의 식당 운영 Flow와 NPC 작업 시스템, 길찾기 및 가구 배치 시스템을 구현했습니다.

## Project Info

* 개발 형태: 팀 프로젝트 [프로그래머 2, 아트 2, 기획 1]
* Engine: Unity
* Language: C#
* 주요 구현:

  * NPC 작업 배정 및 상태 관리
  * A* 기반 길찾기
  * BFS 기반 가구 배치 유효성 검사
  * 손님 및 좌석 관리
  * 식당 운영 Flow

---

## Main Features

### 1. NPC Task Dispatch System

초기에는 각 NPC가 직접 수행 가능한 작업을 탐색하고 선점하는 분산 방식으로 구현했습니다.

하지만 어떤 작업이 대기 중인지 중앙에서 파악하기 어렵고, 여러 NPC가 동시에 작업을 탐색하면서 작업 배정 흐름을 예측하기 어려운 문제가 있었습니다.

이를 개선하기 위해 작업 관리 객체가 대기 중인 Task를 관리하고, 사용 가능한 NPC에게 FIFO 방식으로 배정하는 중앙 Dispatcher 구조로 변경했습니다.

**개선 방향**

* NPC가 직접 작업을 탐색하는 구조 제거
* 대기 Task를 중앙 Queue에서 관리
* Idle 상태 NPC에게 순차적으로 작업 배정
* 작업 생성과 실행 책임 분리

---

### 2. NPC State & Task Execution Refactoring

초기에는 NPC의 이동, 상호작용, 대기 등 여러 동작이 하나의 `ExecuteTask` Coroutine에 집중되어 있었습니다.

기능이 증가하면서 조건문과 예외 처리가 복잡해지고, 새로운 행동을 추가할 때 기존 로직에 영향을 주기 쉬운 구조가 되었습니다.

이를 개선하기 위해 Task 내부 행동을 역할별 Coroutine으로 분리하고, NPC의 현재 상태와 작업 진행 단계를 구분해 관리하도록 리팩토링했습니다.

**개선 결과**

* 이동 / 대기 / 상호작용 등 행동별 책임 분리
* Task 실행 흐름 가독성 향상
* 중단 및 다음 단계 전환 규칙 명확화
* 신규 행동 추가 시 기존 코드 수정 범위 감소

---

### 3. Furniture Placement Validation

플레이어가 테이블과 가구를 자유롭게 배치할 수 있도록 배치 시스템을 구현했습니다.

단순히 해당 위치에 다른 오브젝트가 존재하는지만 검사할 경우, 가구 배치로 인해 NPC가 이동해야 하는 공간이 막히는 문제가 발생할 수 있었습니다.

이를 방지하기 위해 가구를 임시로 배치한 상태를 가정한 뒤 BFS를 수행하여 주요 이동 영역의 연결성이 유지되는지 검사하도록 구현했습니다.

**검증 방식**

1. 배치 예정 영역을 임시 장애물로 처리
2. 이동 가능한 Tile을 기준으로 BFS 수행
3. 필요한 영역까지 접근 가능한지 확인
4. 연결성이 유지될 경우에만 배치 허용

배치 검사 비용은 증가하지만, 실제 검사 영역이 제한적이고 배치 시점에만 수행되므로 런타임 안정성을 확보하는 편이 더 적절하다고 판단했습니다.

---

### 4. A* Pathfinding

Tile 기반 Grid에서 NPC 이동을 위해 A* 알고리즘을 구현했습니다.

각 Tile의 이동 가능 여부를 Node로 관리하고, 시작점에서 목적지까지의 경로를 탐색하여 NPC가 해당 경로를 따라 이동하도록 구성했습니다.

가구가 배치되거나 제거될 경우 변경된 이동 가능 상태를 Pathfinding 시스템에 반영합니다.

## Technical Decisions

### Why Central Dispatcher?

분산 Claim 방식은 구현이 단순하지만, 각 NPC가 독립적으로 작업을 탐색하기 때문에 현재 대기 중인 작업과 향후 작업 배정 결과를 중앙에서 파악하기 어렵습니다.

식당에서는 주문, 서빙, 정리 등 여러 작업이 지속적으로 발생하기 때문에 Task를 관리하는 시스템이 배정을 함께 담당하는 편이 전체 Flow를 제어하기 적합하다고 판단했습니다.

---

### Why BFS Validation Before Placement?

가구가 현재 위치에 물리적으로 배치 가능한 것과 NPC가 해당 배치 이후에도 정상적으로 이동할 수 있는 것은 별개의 문제입니다.

따라서 단순 충돌 검사만으로 배치를 허용하지 않고, 실제 이동 가능한 영역의 연결성을 추가로 검증했습니다.

검사 비용이 추가되지만 배치 시점에만 실행되고 탐색 영역도 제한적이므로, 잘못된 배치로 게임 진행이 불가능해지는 상황을 예방하는 것이 더 중요하다고 판단했습니다.

## Troubleshooting

### Infinite Task Reassignment

하루 전체 운영 Flow를 테스트하던 중 특정 상황에서 로그가 반복적으로 발생하며 메모리 사용량이 증가하는 문제가 발생했습니다.

빈 좌석을 찾지 못한 손님의 작업이 다시 동일한 조건으로 재할당되면서 반복 호출되는 흐름과, 대기 공간의 이동 가능 상태가 정상적으로 복구되지 않는 문제가 함께 발생하고 있었습니다.

원인을 분리하여 다음과 같이 수정했습니다.

* 유효한 목적지가 없는 경우 Task 재할당 제한
* 실패한 작업의 재시도 조건 명확화
* 대기 공간 사용 종료 시 `walkable` 상태 복구
* 착석 위치 복귀 시 A* 경로를 이용하도록 이동 Flow 수정

이를 통해 하루 전체 식당 운영 Flow를 정상적으로 진행할 수 있도록 개선했습니다.
